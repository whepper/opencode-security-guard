# Incident 2026-08-21: shell RC file credential exposure

> Case study, preserved deliberately. No real credential values appear anywhere in this repository.

## Summary

During a routine PATH debugging session, an agent read `~/.zshenv`. The file contained **plaintext API keys**. Their values entered tool output and were transmitted to the model provider — twice — before anyone noticed.

No protected filename was touched. `.zshenv` carried no secret-shaped signal: the permission rules, watcher exclusions, and guard of that deployment all behaved exactly as configured, and the keys still left the machine.

## Root cause

The controls relied on filename classification. Shell startup files are configuration by name and secrets by content, and no filename rule can express that.

> **Filename-based protection alone is insufficient.**

Secondary causes:

- watcher exclusions did not cover startup files (irrelevant anyway once read directly);
- the agent policy did not identify startup files as sensitive;
- the execution-time guard had no reason to intervene: the operation looked like an ordinary permitted `cat`.

## Remediation (as implemented in this repository)

| Control | Where |
| --- | --- |
| Startup files approval-gated (`ask`; `deny` in strict profile) | Layer 1 `SG-RC-001..007` |
| Shell references to startup files gated | Layer 4 `GG-RC-*` + interpreters (`source`) |
| Dedicated secret store denied to reads *and* writes (`~/.config/secrets/`) | Layer 1 `SG-CLOUD-007`, `SG-WRT-006`; Layer 4 `GG-CLOUD-006` |
| Watcher excludes startup files and secret stores | Layer 2 |
| Agent policy names startup files explicitly as sensitive | Layer 3 |
| The exact incident shape is a permanent regression case | `BYP-INC-001..003` in `tests/bypass/cases.jsonc` |
| Credentials migrated out of `.zshenv` into the denied store with restrictive permissions | deployment hygiene |

## Credential response

Exposed keys must be treated as compromised regardless of local remediation: rotate/revoke immediately. Transmission cannot be undone.

## Lessons

1. Secret protection needs both filename **and** semantic controls; neither suffices alone.
2. Shell startup files deserve explicit treatment in every layer.
3. Every discovered bypass becomes a regression test or it will regress.
4. Advisory policy is guidance, never enforcement.
5. Controls need re-verification after upgrades — beta APIs move.
